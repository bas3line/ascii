# ascii.rest/markdown: the spec

Markdown figures: an ```` ```ascii <name> ```` fence in markdown, drawn in
text. A line of words becomes a headline in banner letters with a glint
passing over it; folded stacks become a flame graph; git commands become the
graph `git log --graph` prints. Each figure is an ascii.rest piece, so it
builds in as it is seen, many keep moving while they are in view, and the same
drawing is a page, React, MDX, an animated SVG in a README, a terminal and
plain text in a fence, character for character. That is what makes them ours,
with the art and the kit they are drawn with: `banner()`'s letters, the kit's
3D renderer, its particles, its motion and its seeded random.

This file is the contract for everyone building the family and the site
around it. `CATALOG.md` beside it is what each of the 25 figures draws: its
fence, its grammar, its options, its still and how it plays. Read
`core.ts` and `headline.ts` (the pattern, with `headline.test.ts` and
`examples/markdown/headline.ts`) before anything else.

## 0. Ground rules

- **Each figure is unique.** Its name, its idea, its input grammar and its
  drawing are its own, taken from ascii.rest's art and kit and from the field
  it draws (PlantUML's arrows, git's commands, a man page's usage line,
  boolean algebra, folded stacks, a datasheet's bit masks, relational
  notation, FEN). No figure copies another library's components, their
  names, their input conventions or their drawings.
- **217 stays 217.** The figures are their own family in `src/markdown/`,
  exported as `ascii.rest/markdown`. Nothing goes in `src/pieces/`, `names`,
  `load`, the library's categories or `pieces.length`. `npm run gen` must not
  change `src/pieces/index.ts` or `src/library.ts`; `npm run check` stays
  217/217 (its timing checks can flake under load: rerun a piece alone).
- **Git.** Work only in the worktree you are given. Commits end with a blank
  line and exactly `Co-authored-by: CommandCodeBot <noreply@commandcode.ai>`,
  no other attribution. Never merge (cherry-pick or rebase only), never push
  to main, never run `vercel deploy`, `redeploy` or `promote`, never post
  GitHub comments.
- **Files.** Edit and create files with the Edit and Write tools only (no sed,
  heredocs or scripts that rewrite files); output generated by the repo's own
  scripts is fine. No em or en dashes and no emoji in anything you write:
  code, comments, docs, commit messages.
- **Style.** Comment like `core.ts` and `src/banner.ts`: a header saying what
  the module is, ending with a short usage example; a plain English line above
  each export. Errors through `fail()` from `src/kit/core.ts`, worded the
  kit's way: what is wrong and what to change, `headline's block letters have
  no "#", in "a#b": they draw A to Z, 0 to 9, ...`. `erasableSyntaxOnly` is
  on; imports carry their `.ts` extension.
- **Verify, then report real output.** Never claim what you did not run.

## 1. The API

### 1.1 Entry points

| import | what |
| --- | --- |
| `ascii.rest/markdown` | every figure, the core, `catalog`, `plain()`, `html()`, `figure()`, `paint()`, `make()`, `fromFence()`, `markup()`, `fencesOf()`, `render()`, `start()` |
| `ascii.rest/markdown/remark` | the remark plugin: each ```` ```ascii ```` fence drawn as its figure |
| `ascii.rest/markdown/react` | `<Markdown kind source>` and one component per figure, `<Headline>` |
| `ascii.rest/markdown/element` | `<ascii-markdown kind="headline">` for a plain page |
| `npx ascii.rest md <file>` | a markdown file with every ascii fence drawn as text, or as SVGs, or played |
| `npx ascii.rest add markdown` | the family's source copied into a project, as `add kit` |

### 1.2 Files

| what | where |
| --- | --- |
| a figure | `src/markdown/<name>.ts` |
| its tests | `src/markdown/<name>.test.ts` (node:test, node:assert/strict) |
| its example | `examples/markdown/<name>.ts`, `export default <name>(...)` of the catalog's example |
| its docs | a `## <name>` section of `site/src/pages/docs/markdown-<group>.md` |
| the engine | `core.ts`, `html.ts`, `catalog.ts`, `index.ts`, `remark.ts`, `react.tsx`, `element.ts` |

A figure imports only `./core.ts`, `../kit/core.ts`, `../kit/recipes/checks.ts`,
the kit's drawing and maths, and where it uses them `../banner.ts` (headline,
stamp, ticket), `../kit/shapes3d.ts` and `../kit/recipes/motion.ts` (solid),
`../kit/particles.ts` (confetti). Never another figure, never `src/pieces/`.
A builder does not edit the engine files, `package.json` or the tsconfigs:
it lists what it needs in its report (the export line and `kinds` entry for
`index.ts`, the named component for `react.tsx`, a helper that belongs in
core), and integration adds it.

### 1.3 One shape for every figure

```ts
// src/markdown/<name>.ts
export interface <Name>Data { ... }                     // the parsed form, for data already in JavaScript
export interface <Name>Options extends Common { ... }   // its own options, each default in its comment
export function <name>(source: string | <Name>Data, options?: <Name>Options): MarkdownPiece {
  const data = check(typeof source === "string" ? parse(source) : source);   // statements() or its own reader
  return component("<name>", options, ["own", "options"], (o, room) => ({
    cols, rows, intro, cycle, says, title, label, status, joins,
    draw(s, t, at) { /* s.write(at.x + x, at.y + y, words, TONE) */ },
  }), { frame: "none" });   // its own defaults, only for a figure that is not framed by default
}
```

- `source` is a fence's body; `<Name>Data` is the same thing as data. A
  string is read into `<Name>Data`, then both take one path, checked when the
  piece is made.
- `options` are `Common` (below) and the figure's own, checked by
  `component()` with `optionsOf()`, so a typo throws with "did you mean".
  Options from a fence arrive as strings, numbers and booleans (`fence()`
  reads `width=40` as 40, `cursor` as true).

### 1.4 The grammar

A fence's body is lines, one statement a line, read by `statements()`, or by
a figure's own reader when it has a notation of its own (`CATALOG.md`,
section 1):

| write | means |
| --- | --- |
| a bare word | a name: an actor, a branch, a pin, a place, a style |
| `"words in quotes"` | words to show; `\"` is a quote inside them |
| `key=value`, `key="with spaces"` | an attribute, as the fence's own options are written |
| a blank line | the next block, read with `blocks()` (a sprite's next frame) |

No character means anything else: `!` and `->` stay in the words they are
written in. There is no marker for "the one to read"; where a figure singles
one thing out, its own field decides it, computed or by a named option (git's
HEAD, chess's last move, flame's hottest leaf, bracket's champion, world's
`here=`, pinout's `pulse=`).

### 1.5 Options every figure takes (`Common`)

| option | takes | default |
| --- | --- | --- |
| `title` | words on the top edge, lower case as written; `false` for none | the figure's own (`Body.title`), or none |
| `frame` | `"rounded"`, `"single"`, `"heavy"`, `"double"`, `"ascii"` (+ - \|) or `"none"` | `"rounded"`, or the figure's own default |
| `width` | columns, frame included, 16 to 160 | 48 for a figure of words (`PROSE`), else its content's own width |
| `color` | the accent: `#rrggbb`, `{ light, dark }` or a palette's name | the banners' orange |
| `play` | `"once"`, `"loop"` or `"still"` | `"once"` |
| `speed` | `"slow"`, `"normal"`, `"fast"` or times as fast | `"normal"` |

### 1.6 The core

```ts
// the family
export const GROUPS: { lettering; ornaments; machines; internals; tokens; games; places };
export type Group = keyof typeof GROUPS;
export type Kind = (typeof GROUPS)[Group][number];
export const KINDS: readonly Kind[];
export function groupOf(kind: Kind): Group;

// tones: palette indices, the same on both pages
export const INK = 0, SOFT = 1, QUIET = 2, ACCENT = 3, GOOD = 4, WARN = 5, BAD = 6, VIOLET = 7, MARK = 8, GLINT = 9;

export const COLORS: Record<Tone, { light: string; dark: string }>;

export function clean(text: string, what?: string): string;  // folds typographic quotes, dashes, an ellipsis; throws for the rest

// a fence's body
export function linesOf(source: string): string[];           // \r\n, blank ends and the shared indent removed
export interface Statement { line; words; texts; attrs; tokens; raw }
export function statements(source: string, what?: string): Statement[];
export function blocks(source: string, what?: string): string[][];
export function wrap(words: string, width: number): string[];
export function commas(n: number, places?: number): string;
export function fence(info: string): { lang: string; kind: string; options: FenceOptions };

// time
export function progress(t: number, from: number, to: number): number;          // 0 to 1
export function shown(t: number, from: number, count: number, perSecond: number): number;
export const GLINT_SECONDS = 0.7;

// the frame and the figure
export type FrameStyle = "rounded" | "single" | "heavy" | "double" | "ascii" | "none";
export const BOXES: Record<Exclude<FrameStyle, "none">, string>;   // tl tr bl br across down
export function box(s: Surface, x: number, y: number, w: number, h: number, style?: ..., tone?: number): void;
export type Play = "once" | "loop" | "still";
export interface Common { title?; frame?; width?; color?; play?; speed? }

export const PROSE = 48, WIDEST = 160;
export interface Room { cols: number | undefined; prose: number; max: number }
```

`src/kit/core.ts` has `fnv1a32(text)`, a text's FNV-1a hash, for seeds:
`mulberry32(fnv1a32(text))`.

### 1.7 The figure contract

`component()` does the shared work; a figure lays out its `Body` once and
draws it at any time `t`.

- **Lay out once.** Read, check, wrap and measure in the `make(o, room)`
  callback, not in `draw`. `room.cols` is the inner width asked for with
  `width` (frame and padding taken off), or `undefined`: then a figure of
  words fills `room.prose` (44) and one of its own size takes its content's
  width, up to `room.max`. A body wider than `room.cols`, or past 160 columns
  in all, throws with the width it needs.
- **Draw at t.** `draw(s, t, at)` writes at `at.x + col`, `at.y + row` with
  `s.write(x, y, words, TONE)` or `s.set()`. `t` is build time in seconds; it
  depends on `t` alone, seeded with the kit's `fnv1a32` and `mulberry32`,
  never `Math.random` or `Date`. `at.still` is true for the still: draw
  nothing passing over it (no glint, no dot, no cursor).
- **Intro.** `intro` is how long the build takes at normal speed, at most 3
  seconds, 0 for a figure that never moves (fps 0). `t >= intro` is the
  finished figure, and `t = intro` is its still: what reduced motion, the
  server, `plain()` and a README's fence show.
- **Cycle.** `cycle` is the seconds of a seamless loop the figure plays after
  its build while it is in view; `draw` gives the same frame at `intro` and
  at `intro + cycle`. It makes the piece `idle` (a player keeps drawing it),
  and its `motion` `{ seconds: cycle, from: intro, once: false }`, so a
  README's SVG loops the cycle. A figure with no cycle holds once built, and
  its SVG plays the build once and holds. `play: "loop"` rebuilds and holds
  on a loop that divides a minute; `play: "still"` never moves.
- **Joins.** `joins` are body rows a dashed rule crosses: the frame meets each
  with `├┄` and `┄┤`, and the body draws the `┄` between.
- **Says.** One sentence of what the figure shows, from the data, for screen
  readers and `meta.note`: `"headline: ascii.rest, animated ascii art for web
  pages."`.
- **Glyphs.** Only `drawable()` characters. Words from a source go through
  `clean()` (`statements()` and `blocks()` already do).
- **One ink.** Shape carries what colour carries, so `plain()` reads alone.
- **Tones.** `INK` words and marks; `SOFT` captions, labels, keys; `QUIET`
  lines only; `ACCENT` what moves and what carries a value; `MARK` the one
  thing the figure's own data singles out, at most one run a row; `GOOD`,
  `WARN`, `BAD`, `VIOLET` colours a figure picks for lanes, pieces and inks,
  never a verdict; `GLINT` the passing light.
- **Errors.** Every option and datum checked when the piece is made, with
  `fail()`, naming the line and what it takes.
- **Tests** (`<name>.test.ts`): the catalog's example draws its target still
  exactly through `plain()` and through `fromFence()`; a frame mid build
  differs from the still and the still holds after; for a cycle, the frame at
  `intro + cycle` is the still; `says`; the data form; its own options; at
  least three errors, the kit's way; `svg(piece)` plays once (`/1 forwards/`)
  or loops a cycle (`/infinite/`). And `npm run kit --
  examples/markdown/<name>.ts --at 0,0.3,1` passes.

### 1.8 Hosts

- **A page:** `markup(kind, source, options)` gives the still as `<pre
  class="ascii-md" data-md ...>`; `start()` plays every such figure with
  `paint()` as it is scrolled to, and a later `start()` plays one a stop
  stopped. `paint()` writes spans, redraws only on change, stops once built
  (unless it has a cycle or a loop), holds the still for reduced motion, and
  adds `STYLE` unless `style: false` (a site styling the tones itself).
- **Markdown and MDX:** `remarkPlugins: [ascii]` from
  `ascii.rest/markdown/remark` turns each ```` ```ascii <name> key=value ````
  fence into its figure, as HTML elements, so MDX needs no rehype-raw. A bad
  fence fails the build, naming the fence.
- **React:** `<Markdown kind="headline" font="slim">{source}</Markdown>`, or
  `<Headline font="slim">{source}</Headline>`; the server renders the still
  with `html()`, a client effect calls `paint()`. `"use client"`.
- **A plain page:** `<ascii-markdown kind="headline" font="slim">ascii.rest
  </ascii-markdown>`, its text the body, its attributes the options.
- **A README:** `render(doc)` (and `npx ascii.rest md README.src.md --out
  README.md`) draws each top-level fence as text; a fence shown inside another
  stays as written. `--svg <dir>` writes each figure as an animated SVG for a
  light page and a dark one, in a `<picture>`.
- **A terminal:** `play(piece)` from `ascii.rest/terminal`, or `npx ascii.rest
  md <file> --play`; piped, the still.
- **Copying:** `npx ascii.rest add markdown` (registry item `markdown`,
  needing `core`, `kit` and `banner`; `markdown-react` for React).
- **llms.txt:** each docs page keeps its ```` ```ascii ```` fences as written,
  which is what an agent should write; `/llms.txt` lists each figure with
  what it draws, where it suits, how it moves and its fence.

## 2. The site

Main's design, unchanged: the figures get a section of the home page and
docs pages in its own layout, and nothing else of the site changes.

- **Home:** `<section id="markdown">` just below the scenes, built as the
  category sections are: its head with the count, then a card for each figure
  built, its catalog example baked with `markup()` and played by `start()`
  once the section nears the viewport. The tones take the site's own colours.
- **Docs:** `/docs/markdown/` (what they are, the grammar, the options every
  figure takes, the hosts), then `/docs/markdown-<group>/` for each group, in
  `layouts/Docs.astro`. Each figure's section: what it is for, its fence drawn
  by the remark plugin, its source in a ```` ```md ```` block, its own options,
  a `ts` use and its plain text, which `npm run kit:docs` checks against the
  build.
